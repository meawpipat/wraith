# Implementation Plan: S-protocol

## Overview

This plan builds `packages/protocol` (`@wraith/protocol`) in TypeScript, following the module dependency rules of design.md: `limits.ts`, `text.ts`, `unsafe.ts` and `agents.ts` import nothing from the package; `envelope.ts` imports `message-types.ts` and never the reverse; `src/` never imports `scripts/`, `test/` or `testing/`. It was regenerated from the approved requirements.md and design.md; requirement ids are R-numbers and criteria of requirements.md, and "Design" names a section or Correctness Property of design.md.

Phasing: P0 groups (1 to 7) deliver the package skeleton and scripts so `pnpm -r test` is not vacuous, the TypeScript lib override, limits, text helpers, base schemas, envelope, scope, gate, a first registry subset and the boundaries check. P1 groups (8 to 20) deliver the remaining bodies, the full registry, the 84-code error catalogue, sprite schemas, unsafe tokens, agents and templates, codegen, the `protocol-codegen` hook, fixtures, the repo zod-import check, the remaining property tests and the Workers run. Each group title carries its phase.

Every task or group has a `DoD:` line mapping it to the P0/P1 DoD ids of docs/architecture.md §18.1 and §18.2. Where another spec owns the id the line says "supports" and names the owner (S-crypto for P0-D2/P0-D3 and JCS, S-node-core for the P1-D11 validators, S-ops-packaging for CI, the other P0 hooks for hook behaviour). A DoD coverage table at the end lists what is outside this spec.

Conventions:
- Every Correctness Property of design.md is a required property sub-task (no `*`), cites its property number and requirement ids, and runs through the `pbt(...)` helper using the named constant `PBT_MIN_RUNS = 500` (P1-D6).
- Optional (`*`) is used only for extra unit, snapshot and scan tests. The example tests that give direct evidence for P1-D13 (`E_NAME_TAKEN` 409, bot name rule) and P1-D15 (`approvalTimeoutMin` 0, 1, 240, 241) are required.
- Tasks that touch files outside `packages/protocol` say so. They are limited to what this spec owns (the `protocol-codegen` hook, `tools/check-zod-imports.ts`, `tools/zod-allowlist.json`, the Biome ignore for generated output, fixtures under `fixtures/`) or are "supports" notes in `docs/`. Nothing here edits requirements.md or design.md.
- No task needs a human, money, publishing or a network deployment.
- `src/index.ts` is edited only by the task that says so in each group, so tasks that run in parallel never write the same file.
- Unsafe literals (SI-1, SI-2, R21.2) are never spelled in this file; tasks refer to them by requirement id. Only `unsafe.ts` spells them.
