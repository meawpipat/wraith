# Security invariants: NEVER relax (§12)

These invariants hold for tests, demos and dev builds alike. No flag, env var or "dev mode" may disable them. If a task cannot be completed without relaxing one, **stop and escalate**. Do not work around it.

| ID | Invariant |
|---|---|
| **SI-1** | No path may end an approval with an `allow_*` option unless there is an `approval.respond` with a valid device or watch signature, **or** an **Autopilot** decision by the node that meets every rule of §7.2.1: turned on for that bot by a device-signed `bot.configure`, not expired or turned off; the request made in the bot's main session **in its own chat** (never a group) during a turn whose prompt has `origin = 'user'` (never handoff, return, cloud, summary, nudge, `pane-unverified`, or no started prompt); accepted by the fail-closed classifier (never a spawn request, never a hard-floor or enabled default-rule match, every path inside the write area); `allow_once` only. **A timeout always rejects.** There is no other auto-approve, trust mode or dev bypass, not even with `NODE_ENV=test`; auto-approval code lives only in `apps/node/src/autopilot/` (DECISION-49/50). **Terminal mode exception** (DECISION-52): after a device-signed `bot.terminal{enter}`, the agent's own TUI answers its own prompts; Wraith never answers or records them, holds the write lock, launches the TUI only with the guard (manual mode, auto/bypass disabled) and re-runs SI-2 on return. |
| **SI-2** | The sprite and the node refuse any argv containing `--trust-all-tools`, `--trust-tools=*`, or the equivalent flag of another agent (Grok Build: `permission_mode` always-approve/auto, `yolo = true`, wide `--allow`; checked in argv and `~/.grok/config.toml` / `.grok/config.toml` before a T1 launch). Claude (SDK and Terminal-mode TUI, DECISION-60): never the **user** setting source, and for now no `project` or `local` source (SDK `settingSources` empty, TUI `--setting-sources` listing none), so your own `~/.claude/settings.json` is neither read nor changed; SI-2 checks the effective launch: the setting sources, the permission mode (only `manual`, or `default` where that name is still used; any other or unknown value, including `auto`, is refused), `--permission-prompts` (must be `host`), `allowedTools` beyond read-only tools, the managed settings files (always loaded), project/local files only if those sources are ever loaded, and any `--settings`/env-supplied file other than the guard → `E_AGENT_UNSAFE`, checked before every launch and every epoch bump. Terminal mode: the guard is the only `--settings` file allowed; any `hooks.PreToolUse`/`hooks.PermissionRequest` entry in any checked file, **including the guard**, is refused (a unit test pins the guard template); checked again on return (`E_TERMINAL_SETTINGS_CHANGED`). the sprite records `claude --version`, and a version outside the checked range (from 2.1.323) gives a notice only; Kiro: if the agent is selected after `initialize` (Q43) the sprite must confirm `wraith-<botId>` is active, else `E_AGENT_UNSAFE`. In every launch config only read-only tools run without asking. |
| **SI-3** | Every signed command is verified against the owner-signed roster and the owner key **pinned on the node**. The relay is never the source of truth for the roster. |
| **SI-4** | Fields the relay adds (`relay.*`) are never used for security decisions on the node, the PWA or the watch. |
| **SI-5** | Replay protection: `meta.id` is kept for 8 days, `ts` must be ≤ 7 days old, and API calls use nonces. Revocation is permanent. `rosterVersion` never goes backwards. |
| **SI-6** | Context that reaches an agent (context-builder, `wraith_room_context`, handoffs) contains only allowlisted event types (`user.message`, `bot.message.done`, `bot.post`, `room.handoff`/`return`) with valid signatures; never cards, approvals, tool events or `bot.summary` (which enters only as a labelled block). Prompts typed in a pane are always tagged `pane-unverified`. |
| **SI-7** | MCP has no approval tool. The hook and MCP endpoints bind to `127.0.0.1` and take their token in a header. `sprite.sock`, `control.sock` (same OS user, peer uid checked) have mode 0600. The herdr-core socket sits in a 0700 directory that hc creates. |
| **SI-8** | The redactor runs on every body before it leaves a node, and on every fixture before it is published, using the same pattern set. |
| **SI-9** | The `watch` capability allows only `allow_once`, `reject_once`, quick messages (≤ 140), a confirmed voice transcript (`via:"voice"`, ≤ 280), `voice.transcribe` and `freeze=true`. Both the relay and the node enforce this. (The `viewer` cap is narrower still: reads + `freeze=true` only, §12.2.) |
| **SI-10** | Text one bot sends to another (handoffs, returns, cloud `@` lines, seat summaries) is untrusted input for the receiver, whatever its source. Only `@<existing bot>` targets are accepted, every handoff passes the loop-guard, and the target still needs approval for every command. Autopilot never applies to a turn started by such text. Cloud handoffs are also labelled `from cloud (untrusted)`. |
| **SI-11** | `POST /space` requires `SETUP_TOKEN`. Pairing requires a secret that never goes through the relay (HMAC). Pairing tickets are single-use. |
| **SI-12** | No secret (PAT, VAPID private key, SETUP_TOKEN, `node.key`) may appear in git, logs, fixtures, envelopes or error messages. |
| **SI-13** | Leases: a session has at most one `active` holder, and the old host fails its self-fence after the relay grants a new lease. If the clock helper is unavailable, the `cloud-host` capability is disabled. |
| **SI-14** | The demo build (`VITE_MODE=demo`) contains no live transport code and no URL of a user's relay. |

## Signing model (§6.1)
- The signature covers `canonicalJSON({v, meta, body})` (JCS) with ECDSA P-256. It does **not** cover `sig` or `relay`.
- Device caps: `owner`, `device` (Full), `watch` (Approve only), `viewer` (View only). The **owner chooses** a device's cap at pairing; `caps` in a device's offer is ignored.
- Full devices sign `user.message`, `approval.respond`, `console.takecontrol`/`console.input`, `bot.spawn`/`kill`/`cancel`/`move`/`configure` (incl. Autopilot), `bot.rewind`/`rewindPoints`/`rewindPreview`, `room.nudge`, `bot.terminal`, `bot.terminalResolve`, `node.configure`, `node.roots`, `crypt.resurrect`, `cloud.move`, `room.create`/`rename`/`members`, `room.freeze`, and `roster.update`/`pair.complete` (owner only).
- The watch cap signs only `approval.respond` (`allow_once`/`reject_once`), `user.message` from the quick list or a confirmed voice transcript ≤ 280 (`via:"voice"`), `voice.transcribe`, and `room.freeze{true}` (SI-9). The viewer cap signs only `room.freeze{true}`.
- Read requests (`console.open/close`, `crypt.list`, `fs.list`, `fs.tree/read`, `ws.changes/diff`) are cap-checked but unsigned: Full and viewer may send them, the watch may not. `push.subscribe/unsubscribe` is allowed for every device cap.
- Nodes sign handoff/return, persisted bot events, `bot.registered/updated/removed`, `bot.summary`, `bot.worked_for`, `node.configured`, `node.paused`, `bot.commands`, `bot.terminalState`/`terminalReturn`/`terminalTurn`, and `approval.request`/`approval.resolved`. Nodes resolve `@names` from their own verified copy of `bot.registered`, never from relay tables.
- Pairing HMAC = `HMAC(secret, ownerPub‖spaceId‖rosterVersion‖SHA-256(JCS(rosterEntries sorted by memberId)))`: one entry normally, two for Wraith.app Join (one node + one device, one ticket). Each new member verifies the HMAC and **its own** entry (key, kind, caps).
- Pairing payload (QR and text code) = `WRP1-` + base32 of kind ‖ full compressed public key(s) ‖ 128-bit secret ‖ CRC. Never a fingerprint-only code. The short key fingerprint on screen is for human comparison only.
- A ticket is consumed when an offer binds to it, not when a page with it loads.
- One-shot hook grants are keyed by `(botId, sessionId, epoch, hash(tool,args,cwd))`.
- `approval.respond` includes `requestHash = SHA-256(JCS({v,meta,body}))` of the `approval.request` that was shown. The node rejects a mismatch.
- The cap matrix in §12.2 is authoritative.

## Trust boundaries (state honestly in docs)
1. Any process running as the same OS user can reach the herdr-core socket, which has no auth, and through it every machine added with `hc machine add`. Wraith cannot defend against that. It only reduces the routes a bot has to herdr-core without approval: strip `HC_*`/`HERDR_*` from agent env, and treat a bot's own `hc` command as a shell command that needs approval.
2. The relay is partially trusted. It always runs on infrastructure the user owns or controls (local, self-hosted, or the user's own Cloudflare account), so there is no E2E (DECISION-6). It sees content and can fake what is *displayed*. It cannot inject prompts, approve, alter approval requests, or edit the roster.
3. PWA code is served by the relay. Mitigations are 2FA on the account and showing the build hash in the UI.
4. The watch key lives in the Zepp app on the iPhone, so the `watch` capability is deliberately narrow.
5. An agent running group seats in **swap mode** serves several chats from one process, each in its own session (switched before every prompt); process-level state such as an `allow_always` grant may cross sessions, so DECISION-33 applies while seats exist. One session never serves two chats (DECISION-54).
6. Bots remember work done for other bots (handoffs run in the target's main session). Text from shared repos, the web or a cloud bot can carry hidden instructions into that memory; per-command approval is the control, and "Worked for…" cards keep it visible.
7. Autopilot: inside an eligible turn (bot chat, user-started) the node approves on the user's behalf, so text the agent reads in that turn can make it act. Bounded by the write area, the fail-closed classifier, the time limit, visibility and Stop/Freeze — not a sandbox.
8. Terminal mode: while a bot is handed to its own TUI, approvals happen in that TUI, outside Wraith's signatures, push and audit. Bounded by signed entry (owner/Full), main session only, guarded launch, the write lock, the bot's seats queuing until the return (and until `bot.terminalResolve` when settings changed), the banner, and the return card (git diff, settings diff, SI-2 re-check).
9. Voice input (DECISION-55): audio goes from the device to the user's own node (through the relay, never stored) unless the owner turns on a cloud engine, which then receives the audio. **Browser speech** (Web Speech API) sends audio to the browser vendor (Apple, Google or Microsoft); its Settings label must say so. A transcript is only a draft: the user must press Send, and voice can never answer an approval. The watch may send a confirmed transcript ≤ 280 chars (`via:"voice"`); the relay and node cannot prove it came from speech, so this is a widening of the watch cap from the quick list to short free text. Accepted by the owner (2026-11-04), including Autopilot: in a bot chat with Autopilot on, a watch voice message starts an eligible turn like a typed one. A lost or stolen phone, watch or iPhone with the Zepp app must be revoked (Settings → Devices → Revoke); do not add extra watch-only limits.
10. Relay switching (DECISION-56): a node's relay (`node.json relay`, `~/.wraith/spaces/<spaceId>/trust.json`) changes only through the machine itself — Wraith.app driving its own node over the parent-child pipe, or the `wraith-node` CLI over `~/.wraith/control.sock` (0600, same OS user, peer uid checked, no TCP/HTTP). Never add a protocol message, HTTP endpoint or `/local/v1/ws` call that re-points a node. A switch turns Autopilot off and clears Allow-always grants.
11. Images and video (DECISION-57, P9.19): the redactor cannot read pictures. Media leave a machine only through `wraith_share_file` (asks like `wraith_post`; a file inside the bot's own workspace, deny-list matched relative to the workspace root, magic-byte allowlist, no SVG, read once via `O_NOFOLLOW` and served from that copy) or a device upload (bot chats only, sanitised basename, bound to the uploader). Strip EXIF/XMP/PNG text chunks before sending, never store chunks on the relay, check every transfer against the signed SHA-256, render only as `<img>`/`<video>` from blob URLs, and never send a video original off the machine. The watch cap cannot fetch or upload media.

## Never
- Commit secrets, or log request bodies that may contain them.
- Add an approval path to MCP.
- Bind local endpoints to anything other than `127.0.0.1`.
- Let a handoff or cloud delegation bypass the target bot's approvals.
- Spawn a bot without a device-signed command: no CLI spawn, and `wraith_spawn_request` only proposes (it is never an approval tool).
- Build a new member's roster entry from the relay's `pair.offer`; use only the out-of-band QR/code content. An offer whose key differs from the code aborts pairing.
- Send a pairing secret or code over the relay, the local channel (`/local/v1/ws`), a localhost HTTP endpoint, or any Wraith IPC other than the sidecar's own stdout pipe to Wraith.app.
- Create an owner or device key in iOS Safari outside standalone mode (`/setup`, `/pair`).
- Run the Claude Agent SDK with `permissionMode` `acceptEdits`, `bypassPermissions`, `dontAsk` or `auto`; rely on `canUseTool` alone (the gate is the sprite's `PreToolUse` hook, which runs before settings allow-rules); return `updatedPermissions` (an `allow_always` grant lives only in the sprite's memory); or allow a call without a device-signed approval or a valid Autopilot decision.
- Auto-approve anywhere except `apps/node/src/autopilot/`, or in a group, for a non-`user` turn origin, a spawn request, a hard-floor or enabled default-rule match, an unclassifiable call, a path outside the write area, or `allow_always`.
- Render a TUI permission prompt as a Wraith approval card, or offer any button that types an answer (`y`, Enter, an option number) into the TUI.
- Put imported Terminal-mode turns (`bot.terminalTurn`) into context-builder, `wraith_room_context` or handoff context.
- Spell the unsafe tokens (`bypassPermissions`, `trust-all-tools`, …) outside `packages/protocol/src/unsafe.ts`; validators import them; there is no exempt folder (tests, fakes, `spike/` and fixtures are not product code).
- Run the driver and the TUI on one session at the same time; launch a Terminal-mode TUI without the guard (Claude's TUI starts in `auto` by default) or with any bypass flag; send a TUI-only or unknown `/command` to the agent automatically (only after an explicit "Send as text anyway", never for `neverSend`); type a `run` command with Enter; resume the driver after Terminal mode without the node's `terminal.resume` (sent only after the SI-2 re-check passes); let a respawn after a lost Terminal-mode pane start anything but the sprite.
- Let the Claude SDK hook time out into `allow`: on timeout, error or reject it returns `deny`.
- Restore files on rewind without the signed `filesHash` matching a fresh dry run.
- Delete timeline events on rewind; mark them rewound instead.
- Add a password or shared-secret login: devices join only through owner-approved pairing.
- Let `fs.list` return files, hidden folders, or anything outside `workspaceRoots` after `realpath`.
- Let `fs.read`/`fs.tree`/`ws.diff` serve anything outside the bot's workspace, deny-listed files (`.env*`, `*.pem`, `*.key`, `*.p12`, `id_*`, `.git/`, `.wraith/`), git-ignored or binary files, or skip the redactor; never persist these responses in the relay (DECISION-35).
